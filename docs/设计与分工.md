# 社交故事器：产品与 A 的活怎么变

> 一句话：**不是做一本绘本，是做一个模具。** 家长填 3 个空，30 秒得到一份能念的社交故事；
> 不合格的句子由机器自己打回重写，轮不到你熬夜改。

---

## 0. "器"和"书"差在哪

| | 故事库（书） | 社交故事器（器） |
|---|---|---|
| 内容 | 4 篇成品文案 | 4 个**场景模板** + 1 份规则 + 1 个图池 |
| 家长 | 只能看 | 填变量，生成自己孩子那一份 |
| A 的活 | 写 4 篇作文 | 造 4 个模具、审模具、出图池 |
| 答辩能说 | "我们做了 4 个场景" | "第 5 个场景是加一份 JSON，不是写一篇作文" |
| 质量 | 靠人挑 | 生成即自检，R1-R6 全绿才算过 |

判断依据：**社交故事的有效性建立在"具体到这一个孩子、这一次"**——Carol Gray 那套十项标准的核心就是描述具体情境，通用故事库天然违反这一条。所以"器"不是产品包装，是这套内容形式本身的必然要求。

---

## 1. 输入只有 3 个空

| 槽位 | 例子 | 为什么要有 |
|---|---|---|
| `who` 谁陪着 | 妈妈 / 奶奶 / 老师 | "谁蹲下来"决定孩子信不信这句 |
| `when` 什么时候 | 早上七点 / 午睡前 | 时间锚点让故事能对上真实的一刻 |
| `where` 在哪里 | 桌前 / 床边 / 幼儿园门口 | 地点决定画面 |

**上限是 3 个**。家长在焦虑状态下不会填表单；默认值必须做到"什么都不填也能出故事"。孩子小名（`child`）只用在封面副标题，不进正文——正文永远是"我"。

---

## 2. 生成 → 自检 → 局部重写（这是产品最值钱的一段代码）

```
① 取场景模板  content/scenes/<id>.json
      ↓
② 注入变量    把 {who} {when} {where} 换成家长填的值
      ↓
③ 跑 R1-R6    读 content/rules.json（和 A 的 Python 脚本同一份参数）
      ↓
④ 有几页不过 → 只把这几页退回 ②，整篇重写是浪费
      ↓
⑤ 输出 pages[]：翻页、打印、存成分享链接
```

答辩这句话就够：**"我们不是让 AI 写故事，是让 AI 写能过检查的故事。"**

为什么 ④ 是关键：字数超了、出现"应该"、一页两句——这些错误 80% 是局部的。整篇重来会让已经对的 5 页重新抖一遍，孩子念到的版本每次都不一样。

## 3. A 的产出清单（已经有一部分了）

| 文件 | 状态 | 说明 |
|---|---|---|
| `content/rules.json` | ✅ 已建 | R1-R6 全部参数化，Python 与前端同源 |
| `content/scenes/medication.json` | ✅ 已建 | 吃药场景模板，6 页，可直接当范式抄 |
| `content/scenes/<scene>.json` × 3 | ⬜ | 场景二/三/四，你定 |
| `shots/<id>/01..06.webp` | ⬜ | 每场景 6 张，共 24 张 |
| `check_social_story.py` | ✅ 已升级 | 支持模板模式 |

### 模板必须过"最坏情况"检查

这是"器"特有的坑：模板本身看着短，家长一填长就爆。所以检查器会把每个 slot **按 `max` 填满**再算字数：

```
=== PASS  medication.json  《早上七点，我要吃药》 6 页 / 6 句 [模板] ===
  干净。

# 把 when 的 max 从 6 改成 12 再跑：
  [ERROR] 标题: 标题 16 字（按最长变量算），超过 12 字：早上七点，我要吃药
  [ERROR] 第1页: 24 字（按最长变量算），超过 22 字：早上七点，妈妈把水杯放在桌前。
```

**规矩**：模板正文自己写到的字要 ≤18 字，留 4 字给变量。`medication` 最长的一页最坏情况 18 字。
另外两个必检项：`默认值长度 ≤ max`（不然默认值本身就违规）、`{slot}` 名字必须在 `slots` 里定义（拼错会变成页面上一个裸露的 `{when}`——现场演示会很尴尬）。

## 4. 图池的真正难点

生成器不能实时出图，所以**图必须和文字变量解耦**。一条规则能解决 90% 的问题：

> **图表达动作和物品，不表达身份。**

- 画"有人蹲下来，一只手放在孩子头顶"，不画"妈妈蹲下来" → 换奶奶、换老师、换医生，同一张图都能用。
- 画"一颗白色小药片和水杯"，不画"两粒胶囊加药盒" → 换药型不用重出图。
- 每场景 6 张固定图，变量只换字不换图 → **24 张图依然成立**，D2 的预算不变。

这条写进提示词模板；否则你到 D2 才会发现"奶奶"没有图，然后要么返工，要么在文案里只敢写"妈妈"——那"器"就白做了。

配套：每页的 `alt` 字段就是提示词素材，也是无障碍朗读文本，评委问"盲人家长能用吗"时不用现编。

## 5. 和 B 的接口（这些先冻结）

| 东西 | 谁写 | B 怎么用 |
|---|---|---|
| `content/scenes/*.json` | A | 读 `slots` 生成表单、读 `pages` 渲染 |
| `content/rules.json` | A | 移植成 JS 校验器，参数一模一样，别改数值 |
| `shots/<id>/01..06.webp` | A | 按 `img` 字段取，路径 `shots/{id}/{img}` |
| 注入逻辑 | **B** | A 只定 slot 名字、默认值、`max` |

B 的实现顺序建议：**注入 + 翻页 → 本地存储 → 自检器 → 打印/分享**。自检器放最后做，但接口先留一格（`validate(pages)` 返回不合格页号），不然到 D3 塞不进去。

## 6. 四个场景：现在要做决定

已做：`medication` 吃药。

候选：打针 / 理发 / 上幼儿园 / 见陌生人 / 换牙 / 剪指甲 / 坐地铁。

**挑场景的三个标准**（都满足才选）：
1. 高频——家长真的会搜"孩子不肯吃药 怎么办"；
2. 有明确的"那一刻"能画出来（蹲下来、举着针、坐在椅子上）；
3. 孩子的抵抗是有理由的（疼、怕、陌生），故事才有内容可写。

我建议：**吃药 / 打针 / 理发 / 上幼儿园**——痛感（前两个）、身体被动（理发）、分离（幼儿园），四种不同的焦虑类型，答辩时一句话讲得清覆盖面。
