# A 角色 × Qoder 执行手册（社交故事器版）

> 产品是**生成器**，不是绘本库：家长填 3 个空，现场出一份 6 页社交故事。产品逻辑、图池难点、接口表见
> [社交故事器-设计与分工.md](社交故事器-设计与分工.md)（先读那篇，这篇只讲"怎么让 Qoder 干活"）。
>
> 一句话身份：**你不是文案作者，是模具作者 + 质检员。**

---

## 0. 口径（第三版，定了别再改）

| | 书（错） | 器（对） |
|---|---|---|
| 产出 | 4 篇成品文案 | 4 个场景模板（含 slots）+ 1 份规则 + 图池 |
| 家长 | 只能看 | 填 3 个空，生成自己孩子那份 |
| 你的活 | 写作文、改错字 | 造模具、定默认值、卡字数最坏情况、挑图 |

前两版手册都按"写故事"写的，全部作废；规则 R1-R6 不变，变的是**它以模板形式存在**。

---

## 1. 六条硬规则（模具也必须守）

- **R1** 第一人称"我"、现在时，不出现"你/您"。
- **R2** 一页一句，≤22 个可见字。**模板额外要求：自己写的字 ≤18，留 4 字给变量**。
- **R3** 四型：descriptive / perspective / affirmative / directive；directive 最多 1-2 页，反向比例 ≤50%。
- **R4** 每页至少一个时间/动作/地点线索。"吃药很重要"不算句子。
- **R5** 禁词：应该、必须、不许、不准、不能、总是、永远、乖、听话、勇敢、加油、一定要、记住。
- **R6** 一页一图，图不重复，图与动作严格对应。

结构固定 6 页：`{when}，{who}把水杯放在{where}` → 药片 → 我心里不想吃 → 谁蹲下来 → 我可以先喝水 → 咽下去只要一下。
4 场景 × 6 页 = 24 张图，和原预算一致。

---

## 2. 机检（A 唯一能"客观"的地方）

规则参数已经搬到 `content/rules.json`（前端校验器要读同一份，别在两个地方改数字）。

```bash
python check_social_story.py "content/scenes/*.json"          # 模板模式：按最坏情况算字数
python check_social_story.py "content/scenes/*.json" --json   # 给 CI / 和前端对齐
```

```
=== PASS  medication.json  《早上七点，我要吃药》 6 页 / 6 句 [模板] ===
  干净。
```

**模板模式下检查器会自动做两件事**，这是"器"特有的：

1. **最坏情况字数**——把每个 `{slot}` 按 `max` 填满再算。实测把 `when.max` 从 6 改成 12，立刻报
   `第1页: 24 字（按最长变量算），超过 22 字`。
2. **结构一致性**——`{slot}` 名字必须在 `slots` 里定义（拼错会在页面上留一个裸的 `{when}`，演示时很难看）；`默认值长度 ≤ max`（不然默认值本身违规）。

**对 Qoder 的硬要求**：每造一个模板，自己跑一遍，**ERROR 清零再交**。你拿到手时只剩"这句话孩子听得懂吗"一个问题。

## 3. 给 Qoder 立规矩

新建 `.qoder/rules/hack4good-a.md`（Qoder 认 `.qoder/rules/`，也认 `AGENTS.md`，冲突时 rules 优先）：

```markdown
# A 角色（内容/模具）工作区规则

- 只允许修改 `content/`、`docs/`、`shots/`；禁止读写 `src/`。
- 禁止 git commit / push / checkout，我自己提交。
- `content/rules.json` 的数值不许改（max_len、banned、比例），要改先问我。
- 一次只改我指定的那个场景文件，不许"顺手优化"别的场景。
- 模板里自己写的字 ≤18（留 4 字给变量）；slot 必须有 label/default/max；每页必须有 alt。
- 交付前必须跑 `python check_social_story.py content/scenes/<file>.json`，ERROR 必须为 0。
- 输出中文；不要"赋能/守护/陪伴/科技改变生活"这类词。
```

## 4. 四步，每步一个 prompt

顺序：**先认范式 → 再造三个模具 → 再出图提示词 → 最后演示**。

### Step 1 · 认范式（20 分钟）

`content/scenes/medication.json` 已经写好了，让它照着学，别自由发挥。

```text
先只读，不要改任何文件。
1) 读 content/scenes/medication.json 和 content/rules.json。
2) 写 docs/scene-spec.md，说明"新增一个场景要做什么"：
   slots 怎么写（label/default/max 各是什么意思、max 怎么估）、
   pages 的 6 页骨架、type 怎么选、img/alt 怎么填、
   以及为什么自己写的字要 ≤18。
3) 用 medication 当例子，逐条解释 6 页各自为什么是这个 type。
要求：给后面写模板的人看，别说空话，每条都要能直接照做。
```

### Step 2 · 造场景二（一次只造一个）

```text
按 content/scenes/medication.json 的结构，新建 content/scenes/injection.json（打针）。
读者 4-8 岁，家长念给孩子听。6 页。
硬约束：
- 第一人称"我"、现在时、不出现"你/您"；一页一句
- 模板里自己写的字 ≤18；slot 只用 who / when / where（child 不进正文）
- slot 声明 label/default/max；max 按"最常见的 3 个真实输入"里最长那个估
- type 只能 descriptive/perspective/affirmative/directive，directive 最多 1 页
- 禁词：应该 必须 不许 不准 不能 总是 永远 乖 听话 勇敢 加油 一定要 记住
- 每页必须 img: 01.webp…06.webp 和 alt（一句话描述画面动作，供出图和朗读）
- 结尾停在肯定句，不要停在命令
写完跑 python check_social_story.py content/scenes/injection.json，ERROR 清零，把输出一起给我。
```

**一次一个**：要三个，三个必然一个腔，而且你审不过来。

### Step 3 · 24 条插图提示词（Qoder 只出词，不出图）

```text
读 content/scenes/*.json 的每一页，为每页写一条插图提示词，写入 content/image-prompts.md。
统一风格前缀（每条都带）：「儿童绘本插画，水彩与彩铅混合，柔和暖色，纸纹质感，构图简洁，画面无文字无数字」。
⚠️ 关键约束：图表达动作和物品，不表达身份。
- 不要画"妈妈蹲下来"，要画"一个成年人蹲下来，一只手放在孩子头顶"（换奶奶/老师都能用同一张）
- 不要画"两粒胶囊加药盒"，要画"一颗白色小药片和水杯"
主角一致性：6 岁，短发，黄色卫衣，蓝色裤子，每条写死。
每条写：画面主体（=alt 里那个动作）、镜头（近景/中景/全景）、文字留白位置（左/右/上/下）。
负面词：不要写实照片、不要夸张表情、不要药片堆成山、不要恐怖氛围。
表格列：场景 | 页 | 画面主体 | 镜头 | 留白 | 提示词
```

拿到表 → 图池或这边批量出图 → 你只做"挑"：① 六页是同一个孩子；② 每页有干净地方放字；③ 图里的动作和那页的字是同一件事；④ 换成"奶奶"这张图也不别扭。

### Step 4 · 演示 + 答辩

```text
写 docs/demo-script.md：90 秒现场演示。
0-10s 投屏只有一页绘本，孩子盯着药片，手没动（不说话，让画面说话）；
10-40s 现场请评委说一个场景，选场景 → 填 3 个空（谁陪/什么时候/在哪里）→ 30 秒出 6 页；
40-70s 翻两页念出来，其中一页故意保留"心里有点不想吃"，说明我们写的是孩子的感受不是要求；
70-90s 一句收尾，停 3 秒。
要求：写"手上的动作"和"屏幕上发生什么"，不写功能说明；台词每句 ≤20 字；标出谁说话。
不许说"AI 自动生成"，说"按规则生成"——现场没网也能跑，反而更硬。
```

```text
写 docs/qa.md：5 个问题 + 30 秒回答。
必须覆盖：「这跟给孩子看动画片有什么区别」「谱系孩子差异那么大，模板够吗」
「谁写的这些句子，有特教老师参与吗」「孩子不肯吃药，念个故事真有用吗」「两个人三天能上线吗」。
结构：先承认边界 → 给一个具体做法 → 落回一个孩子的名字。不许喊口号。
```

## 5. 和 B 的接口

- **目录**：`content/` 归你，`src/` 归 B。B 要改文案，找你说，**不许自己动 JSON**。
- **注入逻辑归 B**：你只定 slot 名字、默认值、`max`。B 写"填空 + 翻页"，自检器最后接。
- **命名**：`shots/{id}/01..06.webp`，`id` 用小写英文，别用中文名。
- **提交**：一个场景定稿 commit 一次（`content: injection 模板定稿`）。
- **联调**：让 B 把 `check_social_story.py` 挂进提交前检查，模板坏了当场报。

---

## 6. Qoder 别用的三件事

1. **自己加场景**：它一加就是"刷牙""写作业""分享玩具"，全是没"那一刻"的题，反而稀释主线。
2. **改 rules.json 的数值**：把 max_len 从 22 调到 30，所有检查立刻变绿——这是最典型的"假通过"。
3. **挑图、口吻终审、答辩临场**：这三样评委一问就穿。

---

## 7. 今天 60 分钟

1. 拍板三个场景（建议：打针 / 理发 / 上幼儿园），告诉我名字 + 每个"那一刻"的一句话画面。
2. 把第 3 节规则贴到 `.qoder/rules/hack4good-a.md`。
3. 跑 Step 1，拿到 `docs/scene-spec.md`——这份是给 B 和你自己后面加场景用的。
4. 跑 Step 2 造 `injection` 模板，脚本 ERROR 清零，**自己出声念一遍**：念不顺就是孩子听不懂。
5. commit，跟 B 说"契约冻结"：`content/scenes/*.json`（slots + pages + alt）就是他的渲染输入。
