# 90 秒演示脚本（骨架 · A 负责，答辩前必须念到不卡）

原则：**先让人疼，再给解法，最后落到"能过检查"这个技术点。** 不念功能清单。

| 秒 | 画面 | 说什么 |
|---|---|---|
| 0-10 | 静止页：一个妈妈蹲在诊室门口，孩子背对镜头 | "明天早上要打针。现在晚上九点，她在手机上搜'怎么跟孩子说'。" |
| 10-20 | 搜索结果：越搜越乱 | "搜出来的要么是公众号软文，要么是'你要勇敢'——而这句话本身就会让孩子更紧张。" |
| 20-35 | 切到我们的列表页 | "我们做的是一个生成器。选场景、填三个空：谁陪、什么时候、在哪。" |
| 35-50 | 现场填变量，点生成 | "十秒钟，一本六页的书。每页一句话，一幅画。" |
| 50-65 | 翻三页，念出来 | "注意它没有说'不要怕'。它说'{who}蹲下来，摸摸我的头。''咽下去，只要一下。'" |
| 65-80 | 故意改坏一句，跑机检，红字 | "这是我们真正的核心：规则检查。22 字上限、13 个禁词、引导句不超过一半。" |
| 80-90 | 红字变绿，一句话收 | "所以我们不是让 AI 写故事，是让 AI 写**能过检查**的故事。" |

## 现场要准备的三件事

1. **网**：机检跑在本地脚本上，不依赖网络 —— 这是选它的原因之一。
2. **一份故意坏的文案**：粘贴进去就能出红字，别现场手敲。
3. **真机**：手机开着页面，评委要摸就给。

## 五个必问

| 问题 | 30 秒内的答法 |
|---|---|
| 和 ChatGPT 直接写有什么区别？ | 直接写没有验收标准；我们把"什么是合格的社交故事"写成 6 条可执行规则，能过检、能只重写坏的那一页。 |
| 图片是 AI 画的吗？质量可靠吗？ | 是，24 张统一风格、统一角色；成年人只画背影，所以换人不用换图。 |
| 家长凭什么信？ | 我们不给它"诊断"或"治疗"的话术，只做事件预告；内容规则来自 Carol Gray 的十项标准，且每条都在文档里可查。 |
| 商业化？ | 先做免费工具 + 机构版（医院儿科、特教机构批量生成），不做 C 端订阅。 |
| 两天能做完吗？ | 内容线已完成（4 场景 × 6 页过检），开发线是静态站 + 本地 JSON，已拆成四块并行。 |

## 不要说

- 不说"AI 帮你教育孩子"。
- 不说"治疗自闭症"。
- 不承诺"孩子看完就不哭了"。
