# 90 秒演示脚本（A 负责，答辩前念到不卡）

原则：**先让人疼，再给解法，最后落到"能过检查"这个技术点。** 不念功能清单。

> 和当前实现对齐：页面是 `index.html`，本地 `python -m http.server 8000` 打开；校验规则在 `content/rules.json`，
> 前端（`src/validate.js`）和脚本（`check_social_story.py`）读的是**同一份**规则。

| 秒 | 画面 | 说什么 |
|---|---|---|
| 0-10 | 手机满屏一张图：妈妈蹲在诊室门口，孩子背对镜头 | "明天早上要打针。现在晚上九点，她在手机上搜'怎么跟孩子说'。" |
| 10-20 | 搜索结果（提前截好图，不现场搜）：越搜越乱 | "搜出来的要么是公众号软文，要么是一句'你要勇敢'——而这句话本身就会让孩子更紧张。" |
| 20-35 | 切到列表页（四个场景 + 一句"孩子怕的不是医院，是不知道接下来会发生什么"） | "我们做的是一个生成器，不是绘本库。四个场景，选一个。" |
| 35-50 | 进"自定义"，现场改三个空：孩子小名、谁陪、什么时候 | "填三个空，剩下的它来写——但每一页都得过我们的规则。" |
| 50-65 | 点"开始读"，翻三页，念出来 | "它不说'不要怕'。它说'{who}蹲下来，说放学就来接我。''咽下去，只要一下。'" |
| 65-80 | 回到自定义页，把第 5 页改成"你必须勇敢一点，不要总是哭" | "红字：第二人称、禁词、超长。这条规则在前端和脚本里是同一份 JSON，改不了口径。" |
| 80-90 | 点"演示模式"，提醒卡片弹出 → 自动翻完六页 | "最后一件事：这是家长手机上的样子。到点提醒，点开就是这本书。我们不是让 AI 写故事，是让 AI 写**能过检查**的故事。" |

## 现场要准备的三件事

1. **手机真机 + 提前开好的页面**（同一 WiFi，`http://<电脑IP>:8000`；二维码提前打在纸上）。断网也不怕，页面本地跑。
2. **一句故意坏的文案**，存在备忘录里，现场粘到"自定义 → 第 5 页"输入框，红字立刻出现（不要现场手敲）。
3. **备用的静态截图**：列表页、阅读器第 4 页、演示模式的提醒卡片——万一手机连不上，切截图讲。

## 五个必问

| 问题 | 30 秒内的答法 |
|---|---|
| 和 ChatGPT 直接写有什么区别？ | 直接写没有验收标准；我们把"什么是合格的社交故事"写成 6 条可执行规则（22 字上限、13 个禁词、引导句不超过一半…），能过检，而且**只重写坏的那一页**，不是整篇重来。 |
| 图片是 AI 画的吗？质量可靠吗？ | 是，24 张同一套风格、同一个角色（黄卫衣这个小女孩）；成年人只画背影或侧身、头部不入画，所以换成奶奶、老师都不用换图。原始出图和二十多次退回记录都在 `docs/qoder/` 里。 |
| 家长凭什么信？ | 我们不做"诊断"也不做"治疗"，只做事件预告；文案规则来自 Carol Gray 的社交故事十项标准，每条都写在 `content/rules.json` 里，可查、可改、可被第三方审。 |
| 商业化？ | 先做免费工具；机构版（医院儿科、特教机构）批量生成 + 自定义角色。不做 C 端订阅。 |
| 就你们两个做的？ | A 做内容与前端实现（规则、四个场景、24 张图、页面）；B 负责部署上线、真机测试和答辩时的架构讲述。图是 Qoder 逐张生成的，A 一张一张验收退回。 |

## 不要说

- 不说"AI 帮你教育孩子"。
- 不说"治疗自闭症"。
- 不承诺"孩子看完就不哭了"。
- 不说"两天做完的"——现在是做得完，但别说成赶工出来的。
