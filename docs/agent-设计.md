# 自闭症青少年辅助 agent · 设计（16–18 岁）

> 一句话：**不是陪聊机器人，是"帮我把接下来会发生什么弄明白、把我要说的话说清楚"的辅助工具。**
> 孩子看到的每一句话都是人审过的；AI 只在幕后干活。

## 0. 为什么是 16–18 岁（这个年龄段的特殊性）

这个年龄不是"小一点的大人"，有三件事同时发生：

1. **要独立了，但支持正在撤走**。学校里的资源、老师、家长代办，18 岁后会大幅减少，这叫**过渡断崖**。产品如果只做"哄小孩"，对这个年龄没用；做"过渡期的拐杖"才有价值。
2. **自尊和隐私高于一切**。16–18 岁最不能接受"被当成案例""被监控"。产品语气、视觉、可见性都必须像工具，不像监护。
3. **风险变了**：不再是"排队怎么办"，而是"怎么拒绝""怎么求助而不显得奇怪""网上有人要我的东西""一个人出门怎么办"。

## 1. 为什么不是聊天框

1. **这个年龄最怕的不是"不会说"，是"说错被笑"**。自由聊天把每次不确定都变成一次社交风险。
2. **他们没法评估 AI 说错**，成年人看得出"这回答不对"，青少年更容易直接采信。
3. **出事之后才被发现**，是这类产品最常见的翻车方式。

默认形态是**卡片**：一屏一个决定，最多 3 个选项。16–18 岁能读能打字，所以允许自己写，但写的文字走**意图匹配 + 模板**，不直接喂给模型自由发挥。

## 2. 三类场景（产品边界）

| 场景 | 例子 | 产品怎么接 |
|---|---|---|
| **预演**：把不确定变成可预测 | 第一次实习、大学报到、自己去看病、面试 | 3–6 张卡，按顺序，可重看 |
| **当下求助**：已经不舒服 | 太吵、被盯着、不知道自己在哪、被刁难 | 3 张动作卡 + 恒定"找一个能帮忙的人" |
| **表达**：想说但组织不出来 | 想拒绝、想请假、想投诉、想加入 | 句式卡，填空，可念出来 |

**不在边界内**：情绪陪伴、心理疏导、诊断、社交技巧训练、"变正常"。

## 3. 孩子侧交互

- 一屏一卡组，**最多 3 个选项**；选项 = 图标/图 + **≤16 字**（16–18 岁阅读没问题，但仍不支持长段落）。
- 长解释默认**折叠**，需要时点开。
- **不连问**：一次最多一个问句。
- **出口恒定**：任何一屏右下角「找人帮忙」，位置不随机、不变形。
- **感官可控**：动画/音效/震动可全关；**语音默认关闭**（公共场合放声音对这个年龄是压力）。
- **可见性实时可见**：屏幕常驻一行"这条会被谁看到"，不藏。
- **不做无限流**：单次 15 分钟软提醒，只提醒不阻断。
- 视觉**必须像工具**：中性图标/照片、可读字体、深色模式。现有 60 张绘本插画是 6–8 岁风格，这个年龄用会直接劝退。

## 4. 内容流水线：人审在前，模型在后

```
青少年自己 / 家长 / 老师                孩子侧
────────────────────                  ─────────────
LLM 起草候选卡片                       只读已发布卡片
   ↓                                     ↑
机检（rules.json + checker）              │
   ↓                                     │
人工 approve ─────────────────────→ 发布（版本号）
```

- 模型**永远不直接对孩子说话**。
- 沿用 `content/rules.json` 与 `check_social_story.py`：禁用词、句长、必须含具体动作。
- 每条卡带 `reviewed_by` / `reviewed_at`，答辩时可现场翻。

## 5. 16–18 岁的四个决策（和更小的年龄完全不同的地方）

### 5.1 账号归谁

**账号是青少年自己的，不是家长的。** 家长是可选的协作者（可以是被邀请的、可以随时被移除），不是默认管理员。这一条决定了整个产品的语气。

### 5.2 危机时通知谁

不再写死"通知家长"。设置里让青少年自己指定 1–3 个**信任的大人**（家长、老师、教练、亲戚），危机时通知这个人。

- 没有指定 → 走界面固定卡"现在就打这个电话"，并显示当地紧急号码。
- 这条比"强制通知家长"更可能被接受，也更可能在真出事时被用。

### 5.3 谁在审

默认**自己审**（写卡片的人就是使用者），家长/老师只在孩子邀请时参与。这是和 12–15 岁最大的差别：审核权交给本人，产品只保证"发出去之前过机检"。

### 5.4 内容主题

- 实习/兼职：怎么问问题、怎么说"我没听懂"、怎么请假
- 大学/职校报到：注册、找教室、宿舍冲突
- 自己看病：描述症状、说"我需要人陪着"
- 拒绝与同意：有人让我做我不想做的事、被起哄
- 网络：有人要照片/地址/见面（**硬拦截**）、群聊里被@
- 独立出行：坐错车、找不到路、被尾随
- 被欺凌：怎么留证据、找谁说

## 6. 安全红线（不可协商）

1. **危机词**（自伤、走失、"我不想活了"、被威胁）→ 立刻切固定卡「现在联系你信任的人」+ 通知已指定的大人；**不解释、不劝、不追问**。
2. **不做诊断、不做情绪结论**。可以说"你现在看起来很难受"，不可以说"你有焦虑倾向"。
3. **不评价进步、不奖励"正常行为"**（不奖励眼神接触、不建议压制 stim）。
4. **网络风险硬拦截**：索要住址/照片/见面 → 固定警示卡 + 通知。
5. **不做长时替代**：不承诺"随时都在"，避免依赖。
6. **数据默认本地**，云端可关，删除要真的删。
7. **不做"训练变正常"的叙事**，答辩和文案里都不许出现。

## 7. 技术结构（复用现有仓库）

```
content/rules.json            ← 已有，硬约束唯一真相源
check_social_story.py         ← 已有，机检
content/scenes/*.json         ← 已有，卡片组复用 pages[] 结构
shots/<id>/*.webp             ← 已有 60 张（6–8 岁风），16–18 岁需另做一套
src/app.js                    ← 已有渲染器，加"卡片模式"路由
```

新增最小集：

- `cards/<id>.json`：卡片组（每张 ≤16 字 + 图 + 3 选项 + 可见性 + reviewed_by）
- `agent/tools.*`：4 个受限动作 `clarify` / `next_card` / `escalate` / `remind`
- `agent/review.md`：审核记录格式

## 8. 怎么算做成了

只测一件事：**在真的不舒服的那一刻，能不能在 10 秒内点到他要的那张卡。**
辅助：危机卡是否 100% 触发；家长/老师是否能 3 分钟内改一张卡。

不做"使用时长""日活"这类指标。

## 9. 两周能交付（Hack4Good 口径）

1. 「下次这事怎么办」卡片流（改自 `arrival`/`injection` 的结构）；
2. 三张求助卡 + 恒定「联系信任的人」；
3. 卡片编辑页（自己改字、过机检、发布版本）；
4. TTS 可开（默认关）+ 动画总开关；
5. 危机词 → 固定卡的现场演示（答辩最该演的一分钟）。

## 10. 还没解决的问题

- 16–18 岁和 18 岁以后怎么衔接？毕业就断掉的产品没有人用。
- 没有可信大人可指定的青少年（监护人缺位、寄养）怎么办？
- 无口语 / 用 AAC 的使用者，整套输入方式要另做。
- 自己审卡片意味着"可能写出不安全的卡"，要不要强制二次机检 + 一个"我读一遍"的确认？
