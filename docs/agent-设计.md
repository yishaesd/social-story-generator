# 自闭症青少年辅助 agent · 设计（12–18 岁）

> 一句话：**不是陪聊机器人，是"帮我自己把事情说清楚、把接下来会发生什么弄明白"的辅助工具。**
> 孩子看到的每一句话，都是人审过的；AI 只在幕后干活。

## 1. 为什么不是聊天框

三条原因，按重要性排：

1. **12–18 岁的自闭症青少年最怕的往往不是"不会说"，是"说错被笑"**。自由聊天会把每一次不确定都变成一次社交风险。
2. **他们没法评估 AI 说错**。成年人看得出"这回答不对"，青少年更容易直接采信。
3. **出事之后家长才知道**，这是这类产品最常见的翻车方式。

所以交互的默认形态是**卡片**：一屏一个决定，最多 3 个选项，每句大概率能读完。

**但和更小的孩子不同**：12–18 岁能读能打字，所以允许"自己写"，只是写的文字走**意图匹配 + 模板**，不直接喂给模型自由发挥。

## 2. 三类真实场景（这是产品边界）

| 场景 | 例子 | 产品怎么接 |
|---|---|---|
| **预演**：把不确定变可预测 | 明天换教室、第一次去实习、要跟老师说件事 | 3–6 张卡，按顺序，可重看 |
| **当下求助**：已经不舒服了 | 太吵、人多、被盯着看、不知道该去哪 | 3 张动作卡 + 恒定"找身边的大人" |
| **表达**：想说但组织不出来 | 想拒绝、想加入、想请假 | 句式卡，填空，可念给大人听 |

**不在边界内的**：情绪陪伴、心理疏导、诊断、社交技巧训练、"变正常"。
（这几项要么无证据，要么有害，要么该由专业人士做。）

## 3. 孩子侧交互（具体到像素）

- 一屏一卡组，**最多 3 个选项**；选项 = 图标/图 + ≤14 字（12–18 岁可以读长一点，但仍然不支持长段落）。
- **不连问**：一次交互最多一个问句。禁止"为什么呀""然后呢"。
- **退出口恒定**：任何一屏右下角都有「找人帮忙」，位置不随机、不变形。
- **感官可控**：动画、音效、震动全部可关；没有自动播放的声音。
- **可关掉"被看见"的提示**：界面明确显示"这条会被家长看到 / 这条只在这台手机上"，不藏着。
- **不做无限流**：单次 8 分钟软提醒（比小孩版放宽），提醒不阻断。
- 视觉风格**不能幼稚**：现有绘本插画（黄卫衣小孩）适合 6–8 岁，12–18 岁要用更中性的图标/照片风。这是图库要重做的部分。

## 4. 内容流水线：人审在前，模型在后

```
家长/治疗师侧                      孩子侧
─────────────                    ─────────────
LLM 起草卡片                     只读已发布卡片
   ↓                                ↑
机检（rules.json + checker）         │
   ↓                                │
人工 approve ────────────────→ 发布（版本号）
```

- 模型**永远不直接对孩子说话**。
- 机检沿用现有 `content/rules.json` 与 `check_social_story.py`：禁用词、句子长度、必须含具体动作。
- 每条卡片带 `reviewed_by` / `reviewed_at`，答辩时可现场翻出来。

## 5. 12–18 岁特有的三个决策（和小孩版不一样）

### 5.1 隐私：家长能看到什么

这个年龄最在意"被监控"。硬性分级：

- **求助与危机**：家长可见（这是安全阀，且必须提前告知孩子）。
- **日常浏览与选择**：默认只在本地，家长看不到；孩子可一键删除。
- **界面必须写清楚**：哪条会被看到、哪条不会。**不做事后偷偷上报**。

### 5.2 谁在"审"

12–16 岁：家长/治疗师审；16–18 岁：改成**共同编辑**（青少年可以自己改措辞、提建议），否则必然被弃用。

### 5.3 内容主题变了

不再是"怎么排队、怎么进校门"，而是：

- 分不清同学是在开玩笑还是在嘲弄
- 有人让我做我不想做的事，怎么拒绝
- 小组作业里我不知道什么时候该说话
- 第一次实习/兼职，怎么问问题不显得奇怪
- 网上有人要我的照片/地址（**硬拦截**）

## 6. 安全红线（不可协商）

1. **危机词**（自伤、走失、"我不想活了"、被威胁）→ 立刻切到固定卡「现在去找身边的大人」+ 静默通知家长；**不解释、不劝、不追问**。
2. **不做诊断、不做情绪结论**。可以说"你现在看起来很难受"，不可以说"你有焦虑倾向"。
3. **不评价进步、不奖励"正常行为"**（不奖励眼神接触、不建议压制 stim）。
4. **网络风险硬拦截**：索要住址/照片/见面 → 直接给固定警示卡 + 通知家长。
5. **不做长时替代**：不承诺"随时都在"，避免依赖。
6. **数据默认本地**，云端可关，删除要真的删。

## 7. 技术结构（复用现有仓库）

```
content/rules.json            ← 已有，硬约束唯一真相源
check_social_story.py         ← 已有，机检
content/scenes/*.json         ← 已有，改造成"卡片组"（复用一个 pages[] 结构）
shots/<id>/*.webp             ← 已有 60 张，6–8 岁风格，12–18 岁需另做一套
src/app.js                    ← 已有渲染器，加一个"卡片模式"路由即可
```

新增的最小集：

- `cards/<id>.json`：卡片组（每张 ≤14 字 + 图 + 3 个选项 + 可见性标记）
- `agent/tools.py`（或 js）：4 个受限动作 `clarify` / `next_card` / `escalate` / `remind`
- `agent/review.md`：审核记录格式

## 8. 怎么算做成了（验收指标）

只测一件事：**孩子能不能在 10 秒内点到他要的那张卡，并且在崩溃前用上它。**
辅助指标：家长是否能 3 分钟内改一张卡；危机卡是否 100% 触发。

不做"使用时长""日活"这类指标——那会诱导把人留在里面。

## 9. 两周能交付的（Hack4Good 口径）

1. 一个「明天要发生什么」卡片流（改自 `arrival`/`injection`）；
2. 三张求助卡 + 恒定「找身边的大人」；
3. 家长审稿页（改字 / 禁用 / 看历史 / 可见性开关）；
4. 语音播报（TTS，可关）+ 动画总开关；
5. 危机词 → 固定卡的演示（这是答辩最该演的一分钟）。

## 10. 还没解决的问题（别装懂）

- 12–18 岁跨度太大，14 岁和 17 岁要的东西不一样，是否需要两个版本？
- 「家长可见 / 不可见」的边界，孩子和家长会有分歧，产品怎么仲裁？
- 语音输出对部分青少年是帮助，也可能在公共场合造成压力，默认该开还是该关？
- 无口语或使用 AAC 的青少年，这套卡片要另做一套输入方式。
